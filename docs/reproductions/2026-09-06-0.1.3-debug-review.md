Additional confirmed defects were fixed while testing the requested schema
and lifecycle behavior:

- Result transforms ran in both the kernel and the Foundation. The regression
  returned `parsed:parsed:hello:middleware` before the fix. Foundation now owns
  the single parse after middleware, while the kernel retains its parsed `run`
  for other execution policies and exposes `runUnparsed` for this owner.
- Executor argument types described parsed command outputs, so a string-to-number
  transform could not be called with a valid string. Call sites now accept
  schema inputs; callbacks retain parsed outputs.
- Typed operations rejected incompatible host contexts only after adding a
  type-level context constraint. Both operation construction and typed registry
  middleware binding now check context compatibility.
- Reusing typed middleware with a different registry's same-named operation
  reached a callback with the wrong schema. The new runtime identity check throws
  `COMMAND_MIDDLEWARE_REGISTRY_MISMATCH` before invoking that callback.

## Post-fix quality and boundaries

### CI toolchain follow-up

The first PR verify run failed before consumer assertions: the runner's npm
10.9.8 crashed in Arborist's `loadPeerSet` while resolving the fresh fixture.
The same failure reproduced locally with npm 10.9.8 and 10.9.4 on Node 24,
isolating it from the runner's Node 22 and Linux environment. The identical
consumer script passed with npm 11.19.0. CI now explicitly selects Node 24
and npm 11.19.0 rather than inheriting the runner image's npm 10. No consumer
assertion or dependency constraint was weakened.

Scope: fix-owned files only. Simplification and review were performed serially
in the main thread, per the repository's tool mapping. Manual review was scoped
to these changes because the branch contains unrelated pre-existing work.
Compatibility review preserved the legacy middleware boundary; new runtime
checks retain callback/definition correlation. No known unresolved finding
remains within the four issue acceptance criteria.

The following are explicit API guarantees and limits, also documented in
`src/docs/commands.md` and `src/docs/upgrading.md`:

- The host owns idempotency storage, authenticated actor/tenant scoping,
  fingerprints, conflict policy, retention and transaction boundaries.
- Replay runs permission and prepare, then validates its output. It skips both
  guards, middleware, handler, audit and completion. Replay-sensitive authorization
  must therefore run in the permission checker or prepare lookup.
- Supply `replayResult` when durable output needs a different validator from the
  transforming input-to-result schema. Invalid durable output is rejected.
- Propagate failures out of the enclosing mutation for rollback. Catching and
  swallowing a failure can commit earlier writes; a test demonstrates this.
- Observation completion reports command completion, not the enclosing
  transaction's eventual commit. External action I/O is not transactionally undone.
- A shared helper peer prevents duplicate registries in the supported package
  graph. Arbitrary forced duplicates or separate bundles can still defeat upstream
  identity metadata; the converter cannot recognize a foreign unregistered ID.

The changelog labels 0.1.3 as unpublished. Internal planning and
reproduction artifacts are excluded from the package.
